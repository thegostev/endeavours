IaC in one line

What each concept really solves - and instead of what. Know the one thing, and the details follow from it.

How to use it: cover the "one thing" column, say the line for each row, then compare. Same core = right. The lessons and cards use these exact words. The page grows with each lesson. Last update: Nov 21, 2026 (lessons 0001-0009).

Layer 0 - the mental model

ConceptThe one thingLesson
Software deliveryGet a code change to users safely and repeatably - instead of by hand and hope.0001
ChangeA recorded, reviewable edit - instead of "someone changed something, sometime".0001
BuildTurns code into one fixed, versioned thing - instead of "whatever is on the server".0001
ArtifactThe same bytes in every environment - instead of a different copy in each place.0001
ConfigKeeps what differs between environments outside the artifact - instead of one build per place.0001
DeploymentA known version runs in a known place - instead of guessing what is live.0001
ReleaseUsers get a feature when you choose - instead of when the code happens to land.0001
EnvironmentA separate place per purpose - instead of testing on real users.0001
InfrastructureThe floor every environment stands on - servers, network, storage.0001

Layers 1-2 - delivery

ConceptThe one thingLesson
PipelineEvery change takes the same checked road to production - instead of each person's own way.0002
Continuous IntegrationMerge small changes daily, each checked automatically - instead of one painful merge weeks later.0002
Trunk-based developmentEveryone works on one shared trunk with branches of a day or two - CI in daily practice.0002
Feature flagMerge and deploy unfinished code safely, switched off - instead of hiding it on a long branch.0002
Continuous DeliveryEvery good change is ready for production at any time; a person presses the button.0002
Continuous DeploymentEvery good change goes to production automatically - no button.0002
PromotionThe same artifact moves on, collecting proof - instead of a new build per environment.0002
Blue-green / canaryDeploy without a big bang: switch all users at once and back (blue-green), or a few first (canary).0002

Bonus - Fowler on CI

ConceptThe one thingLesson
Self-testing codeAn automatic test suite on every build, so a conflict in meaning turns the build red - Fowler's prerequisite for CI.0002b
Semi-integrationYou pull from the mainline, but your own work is not shared until the end - a feature branch, even with a CI service on it.0002b
Frequency reduces difficultyIntegration work grows faster than the amount of code - so many small merges cost far less than a few big ones.0002b
Commit build vs secondary buildA fast build with test doubles on every push, then a slower build with end-to-end tests.0002b
Hide work-in-progressMerge unfinished work into the mainline but keep it from users: keystone interface, flags, dark launching, branch by abstraction, parallel change.0002b

Layer 3 - runtime

ConceptThe one thingLesson
ContainerGive the app the same predictable box everywhere - instead of "it works on my machine".0003
Virtual machineA whole pretend computer with its own OS - a stronger wall, at a higher cost.0003
Desired stateYou write what should be true; a loop makes it true and keeps it true - instead of you doing each step.0003

Layer 4 - cloud

ConceptThe one thingLesson
CloudRent servers, networks and storage by API in minutes - instead of buying hardware for months.0004
Availability zoneAn isolated location in a region - copies in two zones survive one zone failing.0004

Layer 5 - Infrastructure as Code

ConceptThe one thingLesson
Infrastructure as CodeKeep infrastructure in files a tool makes real - instead of clicks and memory.0005
DeclarativeGive the end result, and a tool works out the steps - instead of steps that need a known start.0005
IdempotentRunning it again changes nothing if it is already right.0005

Layer 5 - the engine

ConceptThe one thingLesson
PlanKnow exactly what will change before anything changes - instead of finding out in production.0006
StateA record that binds each resource in your files to one real object - instead of guessing which object is which.0006
ProviderA plugin that turns resources into API calls for one platform - so the core knows no cloud.0006
Replace (-/+)The old object is destroyed and a new one is made - for a database, the data goes with the old one.0006

Layer 5 - living with it

ConceptThe one thingLesson
DriftReality changed outside the code - so code, state and reality no longer agree.0007
Remote state + lockOne shared state, one apply at a time - instead of two people changing the same floor at once.0007
ModuleWrite a group of resources once and use it with different inputs - instead of copying folders.0007
StackA piece you apply as one unit, with its own state - so one mistake cannot reach everything.0007

Layer 5 - delivering it

ConceptThe one thingLesson
Infrastructure pipelineEvery infrastructure change gets a reviewed plan, per environment, before apply - instead of applies from laptops.0008
Policy as codeRules that check every plan automatically - instead of trusting tired reviewers with the must-nevers.0008
Immutable infrastructureNever change a live server: build a new one and remove the old - so drift has nowhere to live.0008

Layer 6 - platforms

ConceptThe one thingLesson

The pairs

PairThe difference
Build vs deploy vs releaseBuild makes the thing. Deploy puts the thing in a place. Release lets users use it.
Artifact vs running appThe artifact is the packed, fixed thing in the store. The running app is that artifact alive in an environment, with its config.
Infrastructure vs environmentInfrastructure is the floor. An environment is one use of it: infrastructure plus config, for one purpose.
CI vs Continuous Delivery vs Continuous DeploymentCI: merge daily, checked automatically. Delivery: always ready, a person presses the button. Deployment: no button.
Feature branch vs feature flagA long-lived feature branch hides unfinished work outside trunk. A feature flag hides it inside trunk, switched off.
Container vs VMA container is an isolated process on a shared kernel. A VM is a whole pretend computer with its own OS.
Imperative vs declarativeImperative: you give the steps. Declarative: you give the end result, and a tool works out the steps.
Update in place vs replaceIn place: the same object gets new values. Replace: the old object is destroyed and a new one is made.
Module vs stackA module is reusable code. A stack is one applied piece with its own state.
Provisioning vs configuration managementProvisioning creates the floor's parts. Configuration management sets up what is inside a server.
IaC vs configuration as codeIaC describes the infrastructure itself. Configuration as code keeps app and tool settings in Git.
Infrastructure vs platform vs environmentInfrastructure is the floor. A platform is the road on top of it, as self-service. An environment is one use of the floor.

"Infrastructure" has no "instead of" on purpose: it is the floor itself; the cloud line (Layer 4) says what renting it replaced. The lines are plain readings of the sources in each lesson, not quotes. If a line sounds wrong to you, say so in chat.
