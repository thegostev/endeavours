Course map

The look-alike pairs

Words that people often use as if they meant the same. Each pair gets one line, and the same line in every lesson.

PairThe difference in one lineSettled in
Build vs deployment vs releaseBuild makes the thing. Deploy puts the thing in a place. Release lets users use it.0001
Artifact vs running appThe artifact is the packed, fixed thing in the store. The running app is that artifact alive in an environment, with its config.0001
Infrastructure vs environmentInfrastructure is the floor. An environment is one use of it: infrastructure plus config, for one purpose.0001
Application code vs infrastructure codeApplication code says what the app does. Infrastructure code says what the floor is made of.0001 (first look), 0005
Infrastructure vs platform vs environmentInfrastructure is the floor. A platform is the road on top of it, as self-service. An environment is one use of the floor: infrastructure plus config, for one purpose.0001, 0009
CI vs Continuous Delivery vs Continuous DeploymentCI: merge daily, checked automatically. Delivery: always ready, a person presses the button. Deployment: no button.0002
Feature branch vs feature flagA long-lived feature branch hides unfinished work outside trunk. A feature flag hides it inside trunk, switched off.0002
Container vs virtual machineA container is an isolated process on a shared kernel. A VM is a whole pretend computer with its own OS.0003
Desired state vs actual stateDesired is what you wrote should be true. Actual is what really runs now. A gap that stays open is drift.0003, 0005
Provisioning vs configuration managementProvisioning creates the floor's parts. Configuration management sets up what is inside a server.0008
Infrastructure as Code vs configuration as codeIaC describes the infrastructure itself. Configuration as code keeps app and tool settings in Git.0008
Imperative vs declarativeImperative: you give the steps. Declarative: you give the end result, and a tool works out the steps.0003, 0005
Update in place vs replaceIn place: the same object gets new values. Replace: the old object is destroyed and a new one is made.0006
Module vs stackA module is reusable code. A stack is one applied piece with its own state.0007
Mutable vs immutable infrastructureMutable: change the live server in place. Immutable: never change it - build a new one and remove the old.0008
Portal vs platformThe portal is the front door. The platform is what the door leads to.0009
