Warm-up

Where you are

The big idea

Cloud - the one thing
Rent servers, networks and storage by API in minutes - instead of buying hardware for months.
In a paragraph
NIST, the standard definition, says cloud resources can be "rapidly provisioned and released with minimal management effort". It names five traits: you serve yourself, over the network, from a shared pool, you can grow and shrink fast, and you pay for what you use. For IaC, the most important fact is hidden in the first trait: everything is made by calling an API. The web console is only a friendly face on those API calls.
Picture
A hotel instead of building a house. You ask at the desk (the API) and get a room (a server) in minutes. You pay per night. Cleaning, power and repairs are the hotel's job.
Where the picture stops working
A hotel gives you a finished room. The cloud gives you parts - network, servers, disks, doors - and you must connect them correctly yourself. Most cloud outages and leaks come from wrong connections, not broken parts.

Words you need

API (in the cloud)
The interface the cloud provider offers for every action: create a server, delete a disk, open a port. The web console calls it for you.
region
A separate geographic area with its own data centers, for example eu-north-1 (Stockholm). Regions are isolated from each other.
availability zone (AZ)
An isolated location inside a region: one or more data centers with their own power and network. A region has three or more.
private network (VPC)
Your own network inside the cloud. It decides which parts can talk to each other.
subnet
A part of the VPC in one AZ. A public subnet has a door to the internet, a private subnet has none.
firewall rule (security group)
A rule that says which traffic may reach a part, from where, on which port.
load balancer
One front door that spreads users across the API copies and skips copies that are not healthy.
DNS
The internet's phone book: it turns a name (notekeeper.app) into an address.
managed service
A part the cloud runs for you, for example a managed database with backups and patches done by the provider.
object storage (S3)
Storage for files ("objects") in "buckets", reached over HTTP. No disk to size.
IAM
Identity and Access Management: who may do which action on which resource. Default: nothing is allowed.
resource
Any one thing you create in the cloud: a VPC, a subnet, a database, a bucket, a DNS record, a rule.

The floor, opened

Five moments on the floor

Moment 1 - a user visits

Maria types notekeeper.app in her browser and opens her notes.

Reveal

DNS, load balancer, API, database. DNS gives the browser the load balancer's address. The load balancer picks a healthy API copy. The API reads Maria's notes from the database.

Why: each part does one job, so each can be changed or doubled without touching the others. That is why one user visit already touches four kinds of resources - and why a mistake in any one of them stops everything after it (lesson 0001: the floor holds everything).

Moment 2 - a zone goes dark

A power failure takes down availability zone A in the middle of the day.

Reveal

API copy 2 in zone B keeps serving, because the load balancer stops sending users to zone A. The database standby in zone B takes over as primary. Users may see a short pause during the database switch, but no lost notes.

Why: AWS designs zones to fail separately, and its own docs warn: if all your servers are in one zone and that zone fails, none of them are available. Two copies in two zones turn a zone failure into a short pause. That safety exists only because someone created the second copy, the standby and the health checks - correctly - on the floor.

Moment 3 - the API wants the bucket

The API must save attachments in the S3 bucket. Ben suggests pasting an access key with full admin rights into the API's config.

Reveal

A full admin key in config is a stolen key waiting to happen, and it allows far more than the API needs. Instead, give the API a role that may only read and write that one bucket. That is least privilege.

Why: in IAM, nothing is allowed until a policy allows it, and AWS's advice is to grant only the permissions a task needs. If the API is ever broken into, the attacker gets one bucket, not the whole account. Access rules are resources too - they are part of the floor and need the same care as servers.

Moment 4 - where the database lives

Someone asks why the database is in a private subnet. "It would be simpler if it had a public address, then we could connect from our laptops."

Reveal

From the whole internet. In a private subnet, nobody outside the VPC can even reach the database's door. Only the API, inside the network, may connect - and a firewall rule says exactly that.

Why: layers of walls: the network decides who can reach a part, IAM decides who may act on it. A public database depends on one password alone. Many real data leaks come from storage or databases that were public by mistake.

Moment 5 - count the parts

Count the resources in the figure. Include the ones you cannot see: subnets (2 private, plus public ones for the load balancer), firewall rules, the DNS record, the IAM role and its policy.

No answer here on purpose. Your count is the answer - something like 15 to 25, depending on how you count. Say the difference - the same words in every lesson

Region vs availability zone

A region is a separate area of the world. An availability zone is an isolated location inside one region.

Copies in two zones survive a zone failure. Copies in two regions survive a region failure, at a higher cost.

Network vs IAM

The network decides who can reach a part. IAM decides who may act on it.

Two different walls. A good floor has both.

Public vs private subnet

A public subnet has a door to the internet. A private subnet has none.

Front doors (the load balancer) go public. Data stays private.

Infrastructure vs environment (from 0001)

Infrastructure is the floor. An environment is one use of it: infrastructure plus config, for one purpose.

Staging needs its own copy of this floor - or a share of one.

Which part answers the question?

Each part of the floor answers one kind of question.

Cards for your deck

All API copies run in zone A. Zone A fails. What do users see?

Nothing works: no copy is left. Copies in two zones would have kept Notekeeper up.

Why does the database have a standby in another zone?

To take over as primary if its zone fails, with no lost notes.

Ben wants an admin key in the API's config. What do you offer instead?

An IAM role that may use only the one bucket the API needs - least privilege.

Why is the database in a private subnet?

No door from the internet: only parts inside the network, allowed by a firewall rule, can reach it.

Which part should be public: the load balancer or the API copies?

The load balancer - the one front door. The copies stay private behind it.

What does the web console really do when you click "create"?

It calls the cloud's API for you. Every resource is made by an API call.
